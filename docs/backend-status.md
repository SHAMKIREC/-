# Рядом — состояние серверной части

Создан отдельный Supabase-проект `Ryadom` в `eu-central-1`.

## Реализовано в базе

- Таблицы профилей, ролей, заведений, товаров, заказов, позиций заказа и истории статусов.
- RLS для всех семи таблиц.
- Автоматическое создание профиля покупателя при регистрации.
- Заявка владельца на создание заведения без автоматического одобрения.
- Серверная функция `place_order`: проверка заведения, ассортимента, количества и цены, транзакционное создание заказа.
- `transition_order`: серверная проверка прав и разрешённых переходов статусов.
- `assign_courier`: назначение только диспетчером или администратором.
- Защита от самостоятельного изменения владельцем статуса одобрения заведения.

## Ещё не готово

- Перенос полной SQL-реализации серверных функций в воспроизводимую миграцию репозитория (пока функции применены непосредственно к базе).
- Подключение фронтенда к Supabase Auth, базе и RPC.
- Разделение интерфейсов по авторизованным ролям.
- Настоящая загрузка изображений, карта, расчёт реального расстояния и доставка.
- Уведомления, звуки, тесты авторизации и end-to-end проверки.
- Платёжный провайдер, документы, договоры и согласие реальных заведений.

## Правило запуска

До подключения фронтенда и проверки полного заказа нельзя считать опубликованное приложение рабочим сервисом. Демо-заведения не являются подключёнными партнёрами.

## Безопасность

Никогда не передавать `service_role` в клиентский код. Публикация заведения и назначение курьеров доступны только уполномоченным ролям. Перед реальным запуском провести тесты RLS с разными пользователями.
