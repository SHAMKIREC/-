# Решение: CRM внутри React + Supabase

Выбрана собственная CRM с общей моделью заказов и общей авторизацией. Сторонняя CRM не устанавливалась.

| Критерий | EspoCRM отдельно | CRM в существующем приложении |
|---|---|---|
| Размещение | Дополнительный PHP-сервер и база, резервирование и обновления | Существующие Pages и Supabase; оплата по фактическому тарифу/потреблению |
| Интеграция | API, отображение сущностей и синхронизация состояний | Те же таблицы и транзакционные RPC |
| Интерфейс | Настройка интерфейса и сущностей Espo | Существующие React-компоненты и фирменный CSS |
| Заказы | Отдельная адаптация жизненного цикла | Общая таблица orders и order_events |
| Заведения | Новые сущности и привязка владельцев | merchants и products |
| Курьеры | Специальная интеграция заданий, принятия и маршрутов | Ограниченный список заданий и атомарное принятие в RPC |
| Безопасность | Поддержка двух моделей доступа и интеграционных полномочий | Auth, RLS и проверки RPC; обязательные тесты изоляции |
| Масштабирование | Две системы, очереди синхронизации и мониторинг | Одна база; индексы, пагинация и оптимизация Realtime по мере нагрузки |

Это архитектурная оценка для «Рядом», а не утверждение, что EspoCRM не поддерживает кастомизацию. Официальные требования EspoCRM: PHP, сервер и SQL-база, https://docs.espocrm.com/administration/server-configuration/ . Поэтому установить её на статический GitHub Pages нельзя. Конкретная стоимость инфраструктуры зависит от выбранного хостинга; платные сервисы не создавались.
